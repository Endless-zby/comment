# 携程酒店评价监控系统 - 开发需求文档

## 文档说明

本文档记录项目当前开发进度、已实现功能及待开发需求，用于指导后续迭代开发。

---

## 一、项目概述

### 1.1 项目定位

携程酒店评价监控系统是一款本地部署的 Web 应用，用于自动采集携程平台上指定酒店的用户评价数据，提供评价浏览、统计分析等功能。

### 1.2 技术栈

| 层级 | 技术 | 版本 |
|------|------|------|
| 框架 | Next.js | 15+ |
| 前端 | React | 19+ |
| 语言 | TypeScript | 5+ |
| 样式 | Tailwind CSS | 4+ |
| UI组件 | shadcn/ui | latest |
| 数据库 | SQLite + Prisma | 6+ |
| 爬虫 | Puppeteer | 23+ |
| 定时调度 | node-cron | 3+ |
| 图表 | Recharts | 2+ |

## 三、待开发需求清单

### 3.1 高优先级需求（P0）

#### 3.1.1 仪表盘数据接入

**需求描述**：仪表盘页面当前使用静态数据，需要接入真实API获取统计数据。

**涉及页面**：`src/app/dashboard/page.tsx`

**实现要点**：
- 调用 `/api/reviews/summary` 获取总评价数、平均评分、好评率、差评率
- 调用 `/api/hotels` 获取监控酒店数量
- 计算差评数量（1-2星评价）
- 实现酒店评价概览表格

**预估工作量**：中等

## 四、技术债务清单

### 4.1 代码质量问题

| 问题 | 位置 | 优先级 | 说明 |
|------|------|--------|------|
| 类型定义不完整 | `src/app/api/reviews/route.ts` | P1 | `where` 和 `orderBy` 使用 `any` 类型 |
| 缺少Zod验证 | API Routes | P1 | 请求参数未使用Zod进行验证 |
| 错误处理不统一 | 多处 | P2 | 部分API错误处理不完整 |
| 缺少单元测试 | 全项目 | P2 | 无测试覆盖 |

### 4.2 性能优化需求

| 问题 | 位置 | 优先级 | 说明 |
|------|------|--------|------|
| 评价列表无虚拟滚动 | `src/app/reviews/page.tsx` | P2 | 大量评价时性能下降 |
| 统计查询未优化 | `/api/reviews/weekly` | P2 | 大数据量时查询慢 |
| 浏览器实例未复用 | `review-fetcher.ts` | P1 | 每次拉取重新启动浏览器 |

### 4.3 安全问题

| 问题 | 位置 | 优先级 | 说明 |
|------|------|--------|------|
| 无请求频率限制 | API Routes | P2 | 可能被恶意调用 |
| 无输入验证 | API Routes | P1 | 存在注入风险 |
